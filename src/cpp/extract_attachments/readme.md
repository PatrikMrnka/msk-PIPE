🎯 Project Overview: Muscle Origin & Insertion Extraction via VTK

Context: We are developing a biomechanical pipeline that translates CT-segmented muscles and bones into dynamic 3D simulation models using an OpenSim XML setup.
Goal: Implement a highly efficient C++ program using the VTK library to automatically identify and extract muscle attachment points (Origin and Insertion) by calculating the geometric proximity between a high-density muscle mesh and a bone mesh.
Target Output: The program must generate .vtk point cloud files containing the extracted attachment points, ready to be referenced in the OpenSim <MuscleGeneratorTool> XML setup.

🏗️ Architectural & Implementation Rules

You must strictly follow these C++ and VTK best practices:

Modularity (Decomposition): Do not write a monolithic main.cpp. Separate the logic into clear components (e.g., MeshLoader, DistanceCalculator, VtkExporter). Use .h and .cpp files.

Modern C++: Use C++20 features, smart pointers (std::unique_ptr, vtkSmartPointer), and strictly avoid raw pointers where possible to prevent memory leaks.

Efficiency: The input meshes (from Flying edges CT segmentation) are extremely dense (100k+ vertices). DO NOT use brute-force $O(N^2)$ distance calculations. You must utilize VTK's spatial partitioning structures. Specifically, use vtkStaticCellLocator which is heavily optimized for static, dense uniform meshes and provides much faster build and query times compared to traditional locators.

CMake Build System: Provide a robust CMakeLists.txt. It must properly locate the VTK library. Run CMake with -DVTK_DIR as stated in runner.py in def compile_mask2stl.

Clean Code: Use meaningful variable names. Write extensive, lower-case english comments explaining the "why" and "how" inside complex algorithmic blocks (especially around the VTK locator logic).

⚙️ Core Algorithm Logic (The "How-To")

The core extraction algorithm must follow this sequence:

Data Ingestion: Load the Bone .obj (e.g., pelvis.obj) and the Muscle .obj (e.g., S032_R_Iliacus.obj) using vtkOBJReader.

Spatial Tree Construction:

Initialize a vtkStaticCellLocator.

Set the Bone mesh as the dataset for the locator.

Call BuildLocator() to construct the highly optimized spatial binning structure for the bone surface.

Proximity Query (The Loop):

Iterate through every single point (vertex) of the Muscle mesh.

For each muscle point, use locator->FindClosestPoint(...) to query the nearest point on the Bone mesh.

Calculate the Euclidean distance (note: VTK often returns squared distance, so apply sqrt).

Thresholding:

If the distance is $\le$ a configurable max_distance_threshold (e.g., $3.0$ mm), add this muscle point to a new vtkPoints collection.

Exporting:

Wrap the extracted vtkPoints into a vtkPolyData object.

Export it using vtkPolyDataWriter into standard ASCII .vtk format. (This matches the <point_file> requirement in the OpenSim XML).
